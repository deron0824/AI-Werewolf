## 2. 产品定义

### 2.1 产品目标

1. **可玩的完整对局**：2 真人 + 4 AI 在本地完成一局规则完整、流程闭环（发牌 → 昼夜循环 → 胜负判定）的 6 人局狼人杀，全程无需人工主持。
2. **有灵魂的 AI 玩家**：每个 AI 有形象/头像、符合身份的发言（LLM 生成）与有策略的夜间决策；LLM 不可用时决策由规则引擎兜底，游戏永不卡死。
3. **可演进的架构底座**：身份配置、玩家槽位（真人/AI）、流程引擎均以配置驱动，为未来 9 人局及自定义真人/AI 数量留出扩展点（本次不实现多模式切换 UI）。

### 2.2 用户故事

1. 作为**真人玩家**，我想通过浏览器打开本地界面、输入昵称加入一局，以便和另一位朋友远程（局域网）或同机双标签页一起玩。
2. 作为**真人玩家**，我想在夜晚看到自己的身份牌和技能操作界面（如预言家验人、女巫用药），以便在正确时机做出行动。
3. 作为**真人玩家**，我想在白天按法官指定的顺序发言、查看所有玩家的发言记录并投票放逐，以便参与完整的推理博弈。
4. 作为**游戏组织者**，我想一键开始对局并由法官自动主持全部流程（宣布夜晚、播报死讯、引导发言、统计票数、判定胜负），以便零门槛开一局游戏。
5. 作为**游戏组织者**，我想在设置中配置 AI 大模型接入方式（WorkBuddy 免密钥优先 / 本地填 API Key 兜底），以便在无密钥环境下也能开玩。
6. 作为**围观者/观战玩家**（P2），我想以观战身份进入房间查看全局（含身份），以便复盘或学习 AI 的玩法。

### 2.3 本次 Demo 采用的板子（基于调研确认）

**6 人局「2狼 + 预言家 + 女巫 + 2平民」标准板，屠城规则，无警长。**

选择理由：
- 该板子是 6 人局的公认经典配置（网易官方 6 人局、多家攻略一致），2狼 2神 2民，白天投票/夜晚刀人/查验/用药的人数配比均衡，节奏紧凑，适合 Demo 快速验证；
- 只有 2 张狼牌，狼人"刀口协商"简化为 AI 狼单人决策或简单协同，LLM 负担小；
- 无警长竞选环节，流程引擎复杂度显著降低，6 人局本身也不设警长（官方规则）。

#### 规则要点（Demo 采用）

| 环节 | 规则 |
| --- | --- |
| 板子 | 2 狼人、1 预言家、1 女巫、2 平民（共 6 席，2 真人 + 4 AI） |
| 夜晚顺序 | ① 天黑闭眼 → ② 狼人睁眼刀人（2 狼需统一刀口，可空刀）→ ③ 预言家睁眼验一人（被告知"好人/狼人"）→ ④ 女巫睁眼，法官告知当晚刀口（仅解药未用时），选择：用解药救 / 用毒药毒人 / 不用药；**解药毒药每晚限用一瓶且不可同夜双用**；**女巫不可自救**（首夜被刀也不能用解药救自己） |
| 白天 - 死讯 | 法官宣布"昨夜死亡的是 X 号"（双死则一起报）或"平安夜"；**仅第一夜死亡者有遗言**，之后夜晚死者无遗言直接离场 |
| 白天 - 发言 | 幸存者按座位顺序轮流发言（从死者下一位开始；平安夜则由法官指定起始位），发言可由真人打字或 AI 生成 |
| 白天 - 投票 | 发言结束全体投票放逐，法官报票数，最高票者出局；**出局者（含被放逐者）均有遗言** |
| 同票处理 | 平票者进入 **PK 发言**，其余玩家仅在平票者中再次投票；**再平票则当日为平安日，无人出局**，进入夜晚 |
| 胜负（屠城） | 狼人胜：所有好人出局（好人人数 ≤ 狼人存活人数即提前判狼胜）；好人胜：所有狼人被放逐/死亡 |
| 狼人自爆 | P2：白天投票前狼人可自爆，立即出局并跳入夜晚（AI 触发条件待定） |

> 边界说明：屠边规则、警长/警徽、猎人/守卫等神职、9 人局等均属**未来扩展**，见 §6。

## 3. 技术规范

### 3.1 Requirements Pool

#### P0 — 本次 Demo 必须实现

| # | 需求 | 说明 |
| --- | --- | --- |
| P0-1 | 本地服务 + Docker 部署 | 服务端跑在本机，可 Docker 一键启动；两个真人通过浏览器（局域网 IP 或同机双标签页）加入同一局 |
| P0-2 | 房间与加入流程 | 创建房间 → 真人输入昵称加入（最多 2 席）→ 4 个 AI 自动填充 → 开始游戏；座位号自动分配 |
| P0-3 | 法官（主持人）引擎 | 完整主持：发牌、宣布天黑/天亮、按序唤醒夜间角色、播报死讯/平安夜、引导发言顺序、组织投票与 PK、统计票数、播报遗言、判定并宣布胜负 |
| P0-4 | 6 人局标准板规则引擎 | §2.3 全部规则：夜晚顺序、女巫用药限制、遗言规则、同票 PK、屠城胜负判定 |
| P0-5 | 真人玩家操作界面 | 身份牌展示、夜间技能操作（狼人刀人协同、预言家验人、女巫用药）、白天发言输入框、投票面板、遗言输入 |
| P0-6 | AI 玩家决策引擎 | 夜间行动（刀人/验人/用药/投票）有策略逻辑；白天发言符合角色身份（狼人伪装悍跳或隐忍、预言家报查验、女巫解释用药思路、平民表水） |
| P0-7 | LLM 接入（双路线并列） | **路线 A（优先）**：WorkBuddy 云服务免密钥大模型调用（零成本）。**路线 B（兜底）**：设置界面手动输入 API Key，支持 OpenAI 兼容接口（可配置 base_url / model）。两条路线并列 P0，A 可用则默认 A；**两者均不可用时走规则引擎兜底发言（模板句库），保证游戏可继续** |
| P0-8 | API Key 安全存储 | Key 仅存本地（本地加密文件 / 环境变量 / Docker secret），**永不上传**任何远端；界面输入时不回显明文；不计入任何日志 |
| P0-9 | AI 形象展示 | 每个 AI 玩家有简单头像/形象（可用内置头像集随机分配），界面上区分真人/AI，死亡置灰 |
| P0-10 | 昼夜阶段全局指示 | 界面顶部/全局显示当前是第几天、夜晚/白天、当前阶段（刀人/验人/用药/发言/投票），夜间阶段对无权限玩家显示"请闭眼" |

#### P1 — 应该有（本次尽量实现，架构必须预留）

| # | 需求 | 说明 |
| --- | --- | --- |
| P1-1 | 模式配置化 | 板子（角色数量构成）、真人/AI 数量以配置文件/数据结构定义（如 `roleConfig`、`seatConfig`），代码层面支持生成任意配置的局；本次 UI 只暴露 6 人局 |
| P1-2 | 发言历史与复盘 | 完整对局记录（每晚刀口、查验结果、发言全文、投票明细）可在结束后查看 |
| P1-3 | AI 个性差异化 | 4 个 AI 有不同性格倾向（激进/稳健/演技派/跟风），影响 prompt 风格 |
| P1-4 | 计时与节奏控制 | 发言/投票阶段可配置超时；AI 思考有"打字中"过渡效果，模拟真人节奏 |
| P1-5 | 断线重连 | 真人浏览器断开后可重新加入恢复状态 |

| --- | --- | --- |

| P2-2 | 自由配置真人/AI 数量 | UI 上滑杆配置真人 0-6、AI 补足剩余席位 |

| P2-6 | 多房间支持 | 同时多局并行 |

### 3.2 AI 玩家行为要求

| 维度 | 要求 |
| --- | --- |
| 发言生成 | 由 LLM 生成，输入包含：角色身份与已知信息（查验结果、刀口、队友）、当前局势（存活者、历史发言摘要）、性格人设；输出为口语化中文发言，长度限制（如 ≤120 字） |
| 身份一致性 | 狼人须伪装好人（可悍跳预言家或低调隐藏）；预言家天亮应报查验；女巫说明用药思路；禁止 AI 泄露夜间私密信息给非同阵营 |
| 决策策略 | 刀人：优先刀跳预言家/发言强势者；验人：优先验未验过的可疑位；用药：首夜大概率救、毒药谨慎；投票：基于发言置信度的加权选择。决策可由 LLM 给出理由+选择，规则引擎解析；**解析失败或 LLM 超时（建议 10s）→ 规则引擎兜底**，超时时间可配 |
| 反作弊边界 | AI 的 prompt 中仅注入其角色应知信息（狼知队友、预言家知查验、女巫知刀口），法官引擎负责信息隔离 |
| 可用性降级 | LLM 路线 A → 路线 B → 模板句库 三级降级，任何一级失败不得阻塞流程超过可配阈值 |

```text
│                        法官播报区（上帝头像 🎩）                     │

│  │ 1号 你  │  │ 2号 AI │  │ 3号 AI │      ╔══════════════╗        │
│  │ [👤头像] │  │ [🐺?]  │  │ [🧛?]  │      ║ 你的身份牌     ║        │

│  └────────┘  └────────┘  └────────┘                               │
├──────────────────────────────────────────────────────────────────┤
│  发言/事件流水区（滚动）                                            │
│  [法官] 天亮了，昨夜是平安夜。                                       │
│  [1号·你] 我觉得 4 号发言很躲闪……                                    │
│  [2号·AI 🤖] (打字中…)  我是预言家，昨晚查验 5 号，他是狼人！          │
├──────────────────────────────────────────────────────────────────┤
│  操作区（按阶段切换）                                               │
│  白天: [发言输入框________________] [发送]   投票阶段: [投2号][投4号] │
└──────────────────────────────────────────────────────────────────┘
```

要点：
- **顶部状态栏**：天数 + 昼/夜图标 + 当前阶段名 + LLM 连接状态指示灯；
- **法官播报区**：固定可见，所有公开信息（死讯、遗言播报、票数、胜负）在此输出，带法官专属样式；
- **座位区**：头像 + 昵称 + 存活状态；AI 显示 AI 标识与随机头像，死亡置灰翻牌（可选）；
- **身份牌面板**：仅本人可见自己的身份牌与私密信息（查验记录/用药状态/狼队友）；
- **夜间技能面板**：按角色动态渲染（狼人双人协同确认、预言家选人、女巫三选一），无权限时整体显示"🌙 请闭眼"遮罩；
- **投票界面**：头像点选 + 提交，实时显示"已投票"人数（不显示投给谁），PK 阶段只允许选平票者；
- **操作区**：随阶段切换为发言输入 / 技能操作 / 投票 / 遗言。

### 3.4 Open Questions（待确认）

1. **LLM 路线 A 细节**：WorkBuddy 云服务免密钥大模型的接入方式（SDK/HTTP）、可用模型清单、速率限制与并发额度——需架构师/主理人确认后锁定路线 A 的可行性，不可用则路线 B 直接转正为默认。
2. **真人双开形态**：局域网两台设备 vs 同机双标签页，是否需要房间口令/简易鉴权（防止第三人误入）？建议 Demo 用 4 位房间码。
3. **AI 狼人协同**：2 个 AI 狼是否互相可见并协同刀口（共享一次"商量"轮次），还是各自决策由引擎仲裁（随机/权重取一）？建议后者（简单且不泄露给真人狼）。
4. **发言语言风格**：AI 发言是否需要口语化网络用语 vs 规整书面语？影响 prompt 人设设计。
5. **时长与节奏**：AI 每次发言/决策的目标延迟（建议发言 3-8s 打字动画，决策 10s 超时兜底）？真人发言是否限时？
6. **复盘数据导出**：P1-2 的对局记录是否需要导出 JSON 文件给客户做后续分析？
7. **头像来源**：内置 SVG/Emoji 头像集即可，还是需要客户后续提供素材（本次用内置占位）？

## 5. 验收要点（给 QA 的提示）

1. 一局完整对局可跑通且胜负判定正确（分别构造狼胜/好人胜剧本）；
2. 断开 LLM（拔网线/错误 Key）时游戏仍能以模板句 + 规则决策跑完，不卡死；
3. 女巫规则边界：同夜双药被拒、首夜自救被拒、解药用后不再告知刀口；
4. 平票 PK 流程与二次平票判平安日正确；
5. 两个真人浏览器同时操作互不干扰，夜间私密信息不串屏；
6. API Key 存储本地、日志中无 Key 明文。
